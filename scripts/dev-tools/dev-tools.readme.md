# 🛠️ Codebase Modification Tools

Scripts under this section apply changes (create, update, or delete files) directly to the workspace based on input manifests, diff patches, or scripts.

## 📦 apply_yaml_on_codebase.py

Applies a YAML "generation manifest" (a file create/update/delete list) to the workspace instead of an LLM-authored bash script with `cat <<'EOF'` heredocs.

### Key Features

* **Strict Workspace Root & Path Resolution**: Automatically anchors target files to `WORKSPACE_ROOT` retrieved from `VsCodeSettings` (`scripts/core/VsCodeSettings_gen.py` or auto-detected parent of `scripts/`). Can be executed directly from `scripts/dev-tools` or copied to the workspace root without path breaking.
* **Suppression (Deletion) Guard**: Enforces a strict security check ensuring that file/directory suppressions (`action: delete` or rollback cleanups) cannot execute on paths outside `WORKSPACE_ROOT`.
* **AST Syntax Validation**: Every `.ts`/`.tsx`/`.js`/`.jsx` entry is syntax-checked via the TypeScript parser (`ts.transpileModule`) **before** any file is written to disk. If any entry fails to parse, zero files are written (can be bypassed with `--skipCheckSyntax`).
* **JSX & Java Corruption Pre-Check**: Auto-repairs LLM generation artifacts for `.tsx`, `.jsx`, and `.java` files (e.g., escaped `$`, quoted braces, or truncated callbacks). Includes a regex gate to instantly catch residual JSX corruption signatures.
* **Sanitization Reporting**: Automatically tracks and prints exact replacement counts per file for auto-repairs.
* **Atomic Workspace Rollback**: Takes in-memory file backups before applying. If the subsequent `npm run build` verification fails, all modified/created files inside `WORKSPACE_ROOT` are automatically rolled back to restore a clean workspace. **Note**: When `--disableRollback` or `--skipCheckSyntax` is active, a build failure will display a **Warning** and skip automatic rollback, leaving generated changes on disk for inspection.

Manifest schema:

```yaml
generation:
  files:
    - filename: "BookmarksFeature"    # no extension, no path separators
      extension: "tsx"                 # no leading dot
      path: "webview/src/features/bookmarks"   # workspace-relative directory
      action: create                   # create | update | delete
      content: |-                      # required for create/update, omitted for delete
        import React from 'react';
        ...full file content...
commit:
  message: "✅ feat(bookmarks): short conventional-commit summary"

```

### Usage

```bash
# 1. Direct invocation against a manifest file anywhere in the workspace
python3 scripts/dev-tools/apply_yaml_on_codebase.py update.yaml
# Or if copied/executed at workspace root:
python3 apply_yaml_on_codebase.py update.yaml

# 2. Bypass syntax validation, skip node build, or disable rollback via flags
python3 scripts/dev-tools/apply_yaml_on_codebase.py update.yaml --skipCheckSyntax
python3 scripts/dev-tools/apply_yaml_on_codebase.py update.yaml --disableRollback
python3 scripts/dev-tools/apply_yaml_on_codebase.py update.yaml --skipNodeBuild

# 3. Via the update-from-yaml.sh wrapper (works from dev-tools or copied at root)
./update-from-yaml.sh
./update-from-yaml.sh --disableRollback

```

## 📦 apply_git_diff_on_codebase.py

Applies Bash scripts or Unified Diff patches generated by `prompt-4-external-use-git-diff-replace` (or raw LLM Markdown responses containing `~~~~bash` code blocks).

### Key Features

* **Workspace Root Integrity**: Resolves and validates target paths against `WORKSPACE_ROOT`. Rejects any file path escaping or pointing outside the workspace boundary.
* **Pre-Apply Snapshotting**: Automatically extracts target files (`cat << 'EOF'`, `git apply`, `rm -f`) and backs up their pre-change state into `.diff-backups/`.
* **Multi-Step Rollback History**: Tracks execution sessions in `.diff-backups/history.json`, allowing you to revert $N$ steps back in time.
* **Markdown Code Extractor**: Parses raw `.sh` files or raw Markdown output files containing code blocks.
* **Automatic Build Rollback**: Restores original workspace state if execution or build checks fail.

### Usage

```bash
# 1. Apply a generated script or LLM markdown response file
python3 scripts/dev-tools/apply_git_diff_on_codebase.py path/to/script.sh
python3 scripts/dev-tools/apply_git_diff_on_codebase.py path/to/llm-response.md

# 2. View saved rollback history
python3 scripts/dev-tools/apply_git_diff_on_codebase.py --history

# 3. Rollback workspace changes
python3 scripts/dev-tools/apply_git_diff_on_codebase.py --rollback      # Rollback 1 step
python3 scripts/dev-tools/apply_git_diff_on_codebase.py --rollback 3    # Rollback 3 steps

# 4. Via the update wrapper
./update-from-git-diff.sh

```
