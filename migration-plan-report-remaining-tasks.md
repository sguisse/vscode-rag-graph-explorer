# 🚀 File Exporter Migration Plan

## 📊 1. Gap Analysis Summary

The legacy extension in `sandbox/sources-vscode-files-exporter.yaml` was a native VS Code webview tool with a large command/message router. It supported configuration history, profile freeze/rename/duplicate/new/clear behavior, Explorer context-menu path injection and exclusion, source path validation, open editor and git diff source discovery, error-stack source extraction, guarded export execution, process kill, destination utilities, report metrics, charting, generated file/log/report lists, tree-manifest navigation, filter simulation through the Python engine, rich notifications, and external exchange links.

The migrated code already has a modern React feature under `webview/src/features/exporter` with the expected `/components`, `/hooks`, `/store`, and `/types` directories. It also has migrated Python scripts under `scripts/codebase_exporter`, generated RPC infrastructure, a generic `CodebaseExporterAdapter`, generated API service stubs for `files-exporter` and `files-exporter-history`, and a partially migrated `FilesExporterHistoryAdapter`.

The main remaining architectural gaps are:

- The dedicated shared ports for `file-exporter` and `fe-history` are empty, so generated RPC exposes no exporter-specific API.
- The current React exporter stores profiles locally through `vsCodeApiService.saveUserPreferences` instead of using the backend history adapter and history file semantics.
- `FilesExporterAdapter` is empty, so exporter-specific behavior still lives in `backend/src/extension.ts` stubs or is bypassed through the generic `CodebaseExporterAdapter`.
- `backend/src/extension.ts` still contains exporter command logic and webview lifecycle logic directly; it is not yet extremely lightweight.
- Several legacy UI actions are currently placeholders: add open files, add git diff files, add error stack files, copy latest exported files, and clear destination directory.
- The current export execution does not save history before run, does not stream process stdout/stderr into the terminal, does not kill the active process by PID, and uses a random token estimate instead of deterministic exported-content estimation.
- The files tab lacks backend content-regex filtering and separate generated exports/logs/reports sections.
- The report tab lacks multi-column sorting, totals, chart parity, conflict-aware extension append/move behavior, and deterministic max-file-size conversion from size rejection values.
- The tree manifest generated by the Python exporter is exposed in the report but has no React tree tab with search, regex mode, expand/collapse, standard/extension grouping, tri-state selection, open/reveal, and exclude pattern injection.
- Error-stack analysis has a backend service in `BlastRadiusErrorFilesIdentificatorAdapter`, but the React exporter has no modal workflow; the generated API also fails to forward `includeOutWorkspace`.
- Default configuration and file extension categories are hard-coded in the webview constants instead of being initialized from VS Code settings through shared DTOs.

Implementation must move all Webview/Backend contracts into `/shared`, keep webview interactions behind generated RPC services in `webview/src/services/api`, and ensure the React exporter stays organized by the Feature Pattern:

- `components`: pure visual/layout components and modal views.
- `hooks`: command handlers, validation, history orchestration, export execution, file filtering, tree behavior, and source path actions.
- `store`: Zustand state only.
- `types`: UI-only projections such as tab ids, modal state, validation state, tree view state, and view-model helpers.

## 🧩 2. Webview / UI Remaining Tasks

**Configuration Initialization**

The UI must initialize exporter state from backend defaults, not hard-coded constants alone. A dedicated hook should call `filesExporterApiService.getInitialState()` and hydrate the Zustand store with:

- `defaultConfig`
- `config`
- `historyList`
- `selectedProfileId`
- `historyViewMode`
- `currentRepo`
- `workspaceRoot`
- `fileExtsCategoryGroups`
- `exchangeLinks`
- pending Explorer-injected paths

Files:

- `webview/src/features/exporter/hooks/use-export-configuration.ts`
- `webview/src/features/exporter/store/useExporterStore.ts`
- `webview/src/features/exporter/types/exporter.types.ts`

**History Bar**

The history bar already renders profile selection and actions, but it must add legacy history scope switching:

- Current repository scope vs all repositories.
- Hidden selected profile fallback to default when switching to current-repo mode.
- Freeze/unfreeze through backend history file.
- Rename disabled for frozen profiles.
- Duplicate current screen config with custom display naming.
- Add new profile from backend default config.
- Open history file through backend.
- Reveal history path/folder through backend.
- Clear selected/all history with hard/soft behavior.

All history mutations must call `filesExporterHistoryApiService`, not `vsCodeApiService.saveUserPreferences`.

Files:

- `webview/src/features/exporter/components/HistoryBar.tsx`
- `webview/src/features/exporter/hooks/use-export-history.ts`
- `webview/src/features/exporter/store/useExporterStore.ts`
- `webview/src/features/exporter/types/exporter.types.ts`

**Source Paths**

The source paths section must migrate all legacy handlers:

- Add currently open text editor/tab files.
- Add git modified files since the last commit.
- Open the path under the text cursor line, not always the first line.
- Clear paths and sync backend shared selected-path state.
- Validate paths through backend and mark invalid path rows/field state.
- Warn for paths outside the current workspace.
- Add an error-stack modal workflow.
- Receive Explorer path injections and exclusion messages.

Files:

- `webview/src/features/exporter/components/SourcePathsSection.tsx`
- `webview/src/features/exporter/components/ErrorFilesModal.tsx`

**Filters**

The filters section has basic sort/clear/preset behavior, but legacy parity requires:

- Sort direction toggle per field.
- Explode combined regex expressions into line-based patterns.
- Group extension patterns under configured category comment headers.
- Append vs replace mode for category presets based on Ctrl/Cmd.
- Presets loaded from VS Code settings, not local constants only.
- Conflict-aware append/move/add-anyway modal when adding an extension that already exists in the opposite field.
- Python-backed filter simulation endpoint parity with local JS simulation as a fallback.

Files:

- `webview/src/features/exporter/components/FiltersSection.tsx`

**Destination**

The destination section currently has placeholder handlers. It must implement:

- Copy latest export chunk files to the OS file clipboard via backend.
- Reveal destination in the OS/file explorer.
- Clear destination directory with confirmation handled by backend.

Files:

**Execution**

Export execution must use a dedicated exporter API, not the generic `codebaseExporterApiService` directly from the feature. Required behavior:

- Validate all fields before run.
- Run path-explosion and file-existence validation.
- Show guardrail confirmation for broad/out-of-workspace crawls.
- Save history before the export, respecting frozen profiles.
- Build and display the shell command returned by backend.
- Start exporter process with `standard` mode for normal UI runs.
- Poll process status or consume returned process metadata.
- Kill active exporter process by PID.
- Load export report after completion.
- Copy generated files to OS clipboard when enabled.
- Populate report/files/tree tabs from returned report.
- Keep terminal logs deterministic and sourced from backend process output.

Files:

- `webview/src/features/exporter/hooks/use-exporter-execution.ts`
- `webview/src/features/exporter/hooks/use-export-validation.ts`

- Convert size-rejection min/max strings (`KB` or `MB`) into max-file KB updates.

**FilesExporterAdapter**

All non-history core services belong in `backend/src/services/file-exporter/files-exporter-service.adapter.ts`.

Required methods and VS Code/File System interactions:

- `getInitialState(pendingPaths?: string[])`: use `vscode.workspace`, VS Code settings, repo detection, history adapter, `os.homedir`, and settings-driven extension categories/exchange links.
- `runExport(request)`: call migrated `scripts/codebase_exporter/files-exporter.py`, normalize relative paths, build command preview, save metadata, and return `ExportStatus`.
- `getExportStatus(pid)`: return status plus stdout/stderr log snapshots where available.
- `getExportResult(pid, exportDirectory, timestamp)`: enforce finished process, read report JSON, attach tree manifest/log/report/generated file lists, calculate deterministic token count.
- `killExport(pid)`: kill current process through `PythonScriptExecutionManager`.
- `simulateFilters(request)`: call Python `--mode filter-check` and return match/error details.
- `getOpenEditorFiles(currentPaths)`: inspect `vscode.window.tabGroups` and `vscode.TabInputText`.
- `getGitDiffFiles(currentPaths)`: use existing `GitServiceAdapter`.
- `syncSelectedPaths(paths)`, `getSelectedPaths()`, `clearSelectedPaths()`, `appendExternalPaths(paths)`: maintain backend shared state for Explorer and cross-extension updates.
- `openPathAtCursor(path, lineNum)`: resolve against workspace root, open documents or reveal directories.
- `copyLatestExportedFiles(destDir)`: inspect destination directory for latest `export-YYYY-MM-DD_HH-MM-SS` chunks, skip log/report/tree files, call file clipboard script.
- `copySelectedFilesToClipboard(paths)`: recursively resolve files, enforce 50 files / 5 MB guardrail via returned confirmation requirement or native modal, call clipboard script.
- `clearDestDirectory(destDir)`: confirm and clear directory contents.
- `applyFileFilter(request)`: filter generated file list by filename regex and content regex.
- `openBrowserTab(request)`: open simple browser or external browser and pin when configured.
- `showNotification(request)`: bridge native VS Code info/warn/error notifications.

**FilesExporterHistoryAdapter**

History-only services belong in `backend/src/services/file-exporter/fe-history-service.adapter.ts`.

Required method cleanup:

- Expand the port to include all existing adapter methods.
- Add `getHistoryFilePath()`, `openHistoryFile()`, and `revealHistoryFile()`.
- Add `clearHistoryWithMode(request)` to support selected/all and hard/soft behavior.
- Fix `softClearHistory()` timestamp interpolation bug.
- Normalize `~` in the configured history path.
- Return typed history wrapper DTO instead of `any`.
- Preserve repo ownership when updating frozen/unfrozen profile configs.
- Store and retrieve `historyViewMode` per repo.

**Extension Entry Point**

`backend/src/extension.ts` must become lightweight:

- Keep `activate()` and `deactivate()` only.
- Move webview panel creation/lifecycle into a backend manager.
- Move command registration into a backend command module.
- Replace exporter command stubs with calls into `FilesExporterAdapter`.
- Keep RPC registration centralized through generated registrators.

Candidate files:

- `backend/src/managers/WebviewPanel.manager.ts`
- `backend/src/commands/register-extension-commands.ts`
- `backend/src/services/file-exporter/files-exporter-service.adapter.ts`

## 📦 4. Shared Domain & DTOs

Add or expand shared types in `shared/services/file-exporter/model/file-exporter-model.ts`.

Required domain models:

- `ExportConfig`: already exists, but should remain the canonical view/backend config.
- `HistoryEntry`: already exists.
- `HistoryViewMode = 'scope-current-repo' | 'scope-all-repo'`.
- `HistoryRepoConfig`: `{ repo: string; lastRunConfigId: string; historyViewMode: HistoryViewMode; }`.
- `HistoryWrapper`: `{ config: { repo: HistoryRepoConfig[]; lastRunConfigId?: string; historyViewMode?: HistoryViewMode; exchange?: ExportExchangeLink[] }; history: HistoryEntry[]; }`.
- `ExportExchangeLink`: `{ icon: string; url: string; tooltip: string; height?: string; width?: string; openInVSCode?: boolean; }`.
- `FileExtCategoryGroup`: `{ label: string; includeExtsMenuEnabled?: boolean; excludeExtsMenuEnabled?: boolean; extensions: string[]; }`.
- `FilesExporterInitialState`: default/config/history/current repo/workspace/settings DTO.
- `FilesExporterRunRequest`: current profile id, config, mode, paths, and copy/tree/log flags.
- `FilesExporterRunResponse`: process status, timestamp, export directory, command preview, history result.
- `FilesExporterStatus`: process status plus stdout/stderr snapshots and completion metadata.
- `FilesExporterResult`: pid, timestamp, exportDirectory, report results, generated files, estimated tokens.
- `FilterSimulationRequest` and `FilterSimulationResult`.
- `GeneratedFilesFilterRequest` and `GeneratedFilesFilterResult`.
- `DestinationActionResult` / `ClipboardActionResult`.
- `ErrorStackAnalysisRequest` / `ErrorStackAnalysisResult` if the exporter wraps the existing blast-radius parser.
- `PathValidationResult`.
- `OpenBrowserRequest`.
- `NotificationRequest`.
- `TreeManifest`, `TreeManifestNode`, and related generated file models.

UI-only types must stay in `webview/src/features/exporter/types/exporter.types.ts`:

- `ExporterTabId`
- `ExporterModalState`
- `FieldValidationState`
- `FilterFieldId`
- `SortDirection`
- `ReportSortColumn`
- `ReportSortRule`
- `TreeViewMode`
- `TreeSelectionState`
- `TreeSearchState`
- `ToastViewModel`
